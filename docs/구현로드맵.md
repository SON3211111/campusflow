## 1단계 — DB + 핵심 플로우 (약 10일)

> AI분해 → Picking → 내 태스크 필터 → Dashboard 플로우 완성
> 이게 없으면 발표 불가

### DB 작업 (1일)

**tasks 테이블 필드 추가:**
- `priority` varchar (HIGH/MEDIUM/LOW)
- `is_locked` boolean default false
- `locked_by` varchar (동시 Picking 방지)
- `quick_signal` varchar
- `ai_generated_data` json
- `column_id` varchar (board_columns FK)

**새 테이블 3개 추가:**
- `board_columns` — 커스텀 컬럼 DB 저장 (column_id, project_id, name, position)
- `task_status_history` — 활동 로그 (history_id, task_id, prev_status, curr_status, changed_by, occurred_at)
- `team_communication` — 댓글/채팅 (message_id, project_id, task_id, sender_id, parent_msg_id, content, mention_list, created_at)

**user_schedules + schedule_blocks 추가** (공강 시간 추천용):
- `user_schedules` — schedule_id, user_id, updated_at
- `schedule_blocks` — block_id, schedule_id, category, title, day_of_week, start_time, end_time

### AI 분해 결과 즉시 DB 저장 + Picking UI 개선 (2일)

**핵심 변경 — 분해 시점에 즉시 DB 저장:**
- 현재: 분해 결과 → localStorage 저장 → 팀원이 접속하면 빈 화면
- 변경: 분해 완료 → **즉시 DB 저장 (`assignee_id = NULL`)** → 팀원이 언제 접속해도 같은 결과 로드
- `TaskBreakdownPage`에서 AI 응답 받는 순간 `/workspaces/{id}/tasks` POST (assigneeId 없이)

**Picking UI 변경:**
- 현재: 한 사람이 모든 팀원 슬롯에 드래그 배정
- 변경: 팀원 각자가 **본인 슬롯에만 드래그** → DB에서 `assignee_id IS NULL` 태스크 로드
- "Pool로 보내기" 버튼 제거 — 분해 시점에 이미 서버에 저장됨

**구현 내용:**
- AiTaskPage 시작 시 DB에서 `assignee_id IS NULL` 태스크 로드 (localStorage 대체)
- 본인 슬롯에만 드래그 가능 (타인 슬롯 드롭 비활성화)
- 드래그 시 즉시 서버에 `is_locked = true`, `locked_by = userId` 저장
- 5초 폴링으로 다른 팀원이 가져간 태스크 화면에서 제거 (중복 선택 방지)
- "보드로 보내기" → `assignee_id = userId` 확정 저장

> 발표 시연: 분해 후 팀원들이 각자 접속해서 드래그하는 장면이 자연스럽게 연출됨

## 시연 핵심 플로우 (발표 시나리오)

```
1. 워크스페이스 생성 → 팀원 초대
2. AI에 프로젝트 설명 입력 → 태스크 자동 분해
3. AI 분해 완료 → 즉시 DB 저장 (assignee_id = NULL)
4. 팀원들이 각자 AiTaskPage 접속 → 본인 슬롯에 드래그 (Picking)
5. "보드로 보내기" → 칸반 보드에 각자 assignee로 저장
6. 보드에서 "내 태스크만" 토글 → 본인 업무 상태 관리 (드래그앤드롭)
7. 팀원 B가 상태 변경 → 팀원 A 화면에 실시간 반영 (WebSocket)
8. Dashboard에서 팀 진척 + 기여도 + 병목 태스크 확인
```
